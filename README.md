# Fallacy Finder AI v1.2 — Keyword-First + Clarify/Challenge/Respond

This version is designed for low-token API use and practical conversation help.

## What changed

The server no longer asks AI to search the full 100-fallacy catalog. It searches **all 100 locally first** using:

- a dedicated keyword/phrase bank for every fallacy;
- claim-type detection (11 claim identifiers);
- group signals;
- structural pattern rules for high-value fallacies;
- weighted local scoring.

Only the top **8** candidates are normally sent to AI (configurable from 5–12). AI's job is to reason about those candidates, decompose the claim, decide what still needs clarification, and choose the best match. This greatly reduces token usage.

The local knowledge base now contains **776 keyword/phrase signals across all 100 fallacies**, plus a local toolkit for every fallacy that is **not generated by AI at runtime**:

1. **Clarify before labeling** — qualifying questions that test whether the fallacy actually fits.
2. **Challenge the reasoning** — questions that expose the weak logical step without assuming the conclusion is false.
3. **Response / rebuttal options** — Curious, Direct, and De-escalating wording.

The UI displays these tools underneath every fallacy that AI selects.

## Request flow

`Exact claim → local search across 100 → top 8 candidates → AI clarification/reasoning → likely fallacy → clarify/challenge/respond toolkit`

A fallacy match is never treated as proof that the underlying conclusion is false.

## Deploy over your existing Render app

You do **not** need a new API key or a new Render service.

1. Replace the files in your existing `fallacy-finder-ai` GitHub repository with the contents of this folder/ZIP.
2. Commit the changes.
3. Render should automatically redeploy from GitHub.
4. Keep your existing `OPENAI_API_KEY` environment variable.
5. After deploy, open:

   `https://YOUR-RENDER-URL.onrender.com/api/health`

You should see:

```json
{
  "mode": "local-keyword-first-routing",
  "candidate_limit": 8,
  "fallacies": 100
}
```

## Optional Render environment settings

- `OPENAI_API_KEY` — required
- `OPENAI_MODEL` — defaults to `gpt-5.6-terra`
- `CANDIDATE_LIMIT` — defaults to `8`; allowed range is 5–12

If your API tier is very restrictive, set `CANDIDATE_LIMIT=6` without changing code.

## Zero-token local routing test

The app includes a debugging endpoint that searches the entire catalog locally without calling OpenAI:

`POST /api/route`

JSON body:

```json
{"claim":"You always ignore me because you wanted to punish me."}
```

It returns the top locally detected candidates, matched wording signals, and each fallacy's clarification/response toolkit. This is useful for checking the keyword engine independently of AI.

## Safety / interpretation

- Keywords are routing signals, not verdicts.
- Feelings do not need proof to exist; the explanation attached to the feeling may still need support.
- Impact does not automatically prove intent.
- Pattern claims need scope, frequency, opportunities, and exceptions.
- A fallacy does not prove that the conclusion is false.


For easy review/editing, `knowledge/fallacy-keyword-toolkit.csv` contains all 100 fallacies, their keyword banks, clarification questions, challenge questions, and three response styles.
